NFL Betting Prediction Model

Didn't beat the market

I built an end-to-end pipeline that predicts NFL game winners from 19 seasons of data (2006–2024) and tests whether betting on its picks would have made money. It didn't. The sportsbook's own odds predicted games better than my models, and the bets the model chose lost the whole bankroll in the backtest. I'm including it because figuring out why it failed taught me as much as the projects that worked.

4,997Games modeled
55Features per game
906,567Play-by-play rows
3,611Backtest bets

How it works

  1. Collect. Pulled schedules, closing odds, and play-by-play data with nfl_data_py, then rolled the plays up into 10,292 team-game rows.
  2. Clean. Dropped 136 games missing stats or odds, leaving 4,997.
  3. Build features. Rolling 3- and 5-game team stats (like offensive EPA per play), Elo ratings, and rest and travel, using only information available before kickoff.
  4. Train. Logistic regression and random forest, trained on 2006–2022 and tested on 2023–2024.
  5. Backtest. Walk-forward test from 2009 to 2024. The model retrains each season, and it bets when its expected value beats the odds by at least 2%. I tested flat and Kelly bet sizing.

Sleeper New-User Usability Study

Status: proposed study, no data collected. This is the full plan for a large-sample usability study, along with the code I would use to collect, clean, analyze, and graph the data. There are no results in it. A study this size needs around 180 participants, which I can't recruit on my own right now, so I built the project to be ready to run if I get access to a larger group.

This is an independent portfolio project. I am not affiliated with, sponsored by, or endorsed by Sleeper or any other company named here.

1. Research question

How easily can new users understand and complete common fantasy-sports tasks in a mobile fantasy app?

I'm using Sleeper as the example app. It has grown quickly because of its social features, and a lot of its new users are either switching from ESPN or Yahoo or have never played fantasy before. If someone can't figure out how to set a lineup in their first week, there's a good chance they don't come back.

Sub-questions

  • Which of five core tasks are the hardest for first-time users?
  • Does fantasy experience (new to fantasy, daily fantasy only, or season-long) change how well people do?
  • How usable do new users rate the app overall?

Hypotheses

  • H1: Tasks that live deeper in the app (making a lineup change, finding recent stats) will have lower completion rates and longer times than tasks on the main screens.
  • H2: People who are new to fantasy will complete fewer tasks than people who already play season-long fantasy on another app.
  • H3: The average System Usability Scale (SUS) score will be at or above 68, which is the commonly used benchmark for average usability.

2. Why this needs a large sample

A small test with about 5 people is good at finding the biggest problems in an app, but it can't tell you whether one group of users struggles more than another. To test H2, I need enough people in each experience group to compare them.

I used a standard power calculation for comparing two completion rates. To reliably detect a difference of 50% vs. 75% between two groups (80% power, alpha = .05), I need about 58 people per group. Rounding up to 60 per group across three groups gives a target of 180 participants. Recruiting 180 first-time users and paying for a remote testing platform is not something I can do by myself right now, which is why this is a plan and not a finished study.

3. Study design

  • Type: Unmoderated remote usability test. Participants complete tasks on their own phone while a testing platform (for example Maze or UserTesting) records their screen and timing.
  • Pilot first: Before the full launch I would run 5 moderated sessions to make sure the task wording is clear and the timing works.
  • Setup: Every participant joins the same test league so everyone sees the same roster and matchup.
  • Order: Each person completes all 5 tasks in a random order, which keeps the order of the tasks from affecting the results.
  • Length: About 20 minutes, including the surveys.

Screener (before the test)

  • Have you ever used the Sleeper app? (must answer No)

  • What kind of phone do you use? iPhone / Android

After each task

  • Overall, how difficult or easy was this task? (1 = Very difficult, 7 = Very easy)
  • How confident are you that you completed this task correctly? (1 = Not at all, 5 = Completely)

After all tasks

  • How easy was the app to navigate? (1 = Very hard, 5 = Very easy)
  • Overall, how confident were you that you completed the tasks correctly? (1 to 5)
  • System Usability Scale, 10 statements rated 1 (Strongly disagree) to 5 (Strongly agree):
    1. I think that I would like to use this app frequently.
    2. I found the app unnecessarily complex.
    3. I thought the app was easy to use.
    4. I think that I would need the support of a technical person to be able to use this app.
    5. I found the various functions in this app were well integrated.
    6. I thought there was too much inconsistency in this app.
    7. I would imagine that most people would learn to use this app very quickly.
    8. I found the app very cumbersome to use.
    9. I felt very confident using the app.
    10. I needed to learn a lot of things before I could get going with this app.
  • What, if anything, was confusing?
  • What did you like?
  • What would you change?

8. Analysis plan

I wrote the analysis in both Python and R so it can be run in either one. Both versions make the same tables and graphs.

  • Completion rate for each task, with a 95% confidence interval (Wilson method, which works well for percentages).
  • Time on task for successful attempts only. Task times are usually skewed by a few slow people, so I report the median and the geometric mean instead of the regular average.
  • Average ease, confidence, and misclicks for each task.
  • SUS score for each person (0 to 100), then the average and spread for the whole sample.
  • Group comparisons: chi-square tests for completion by experience group (H2), and a Kruskal-Wallis test for SUS scores by group.
  • Usability issues: I code the recordings and written answers into issue categories and count how many people hit each one.

10. Turning results into recommendations

Each major problem I find would get a severity rating and a recommendation written in this format:

PartWhat goes in it
FindingThe problem, in one sentence
EvidenceThe numbers behind it, like completion rate, time, and how many people hit it
RecommendationA specific change to the app
Expected impactWhat should improve, and a target to check in a follow-up test

Severity is based on how many people hit the problem and whether it stopped them from finishing the task. I would pick the top recommendation and make a design mockup of it to test in a follow-up study.

11. Limitations

  • Unmoderated tests can't ask people follow-up questions in the moment, so some reasons behind mistakes may be missed.
  • A test league isn't the same as a real league with friends, so people may care less about the outcome.
  • Recruiting through panels and online communities won't perfectly match everyone who downloads the app.
  • Apps update often, so the tasks and the competitor comparison need to be checked right before testing.

12. What I learned from planning this

Planning this study showed me how much the sample size depends on the question. Five people would be enough to find the biggest problems, but comparing experience groups takes a lot more. It also made me think about what counts as success before collecting any data, since "finished the task" and "finished it without help" can tell very different stories. Writing the cleaning and graphing code ahead of time means the analysis is decided before I see the results, which keeps me from picking the numbers that look best.

"""
Sleeper New-User Usability Study - analysis and graphs (Python)
Joshua Schulz | Independent portfolio project, not affiliated with Sleeper.

Reads the clean data files in ../data (see the data dictionary in the study plan)
and writes summary tables to ../output and graphs to ../figures.

Run:  pip install pandas numpy scipy matplotlib
      python analysis.py
"""
from pathlib import Path
import numpy as np
import pandas as pd
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
from scipy import stats

ROOT = Path(__file__).resolve().parents[1]
DATA, OUT, FIG = ROOT / "data", ROOT / "output", ROOT / "figures"
OUT.mkdir(exist_ok=True)
FIG.mkdir(exist_ok=True)

TASKS = {
    "T1": "Find a player's upcoming game",
    "T2": "Find your team's matchup",
    "T3": "Make a lineup change",
    "T4": "Find league info and chat",
    "T5": "Find a player's recent performance",
}
GROUPS = ["New to fantasy", "Daily fantasy only", "Season-long player"]

# ---------- 1. Load and check the data ----------
people = pd.read_csv(DATA / "participants.csv")
tasks = pd.read_csv(DATA / "task_results.csv")
survey = pd.read_csv(DATA / "survey.csv")

assert tasks["outcome"].isin(["success", "fail", "gave_up"]).all(), "outcome must be success, fail, or gave_up"
assert tasks["seq_ease_1to7"].between(1, 7).all(), "SEQ must be 1-7"
assert tasks["confidence_1to5"].between(1, 5).all(), "confidence must be 1-5"
tasks["success"] = (tasks["outcome"] == "success").astype(int)
tasks = tasks.merge(people[["pid", "fantasy_experience"]], on="pid", how="left")
N = tasks["pid"].nunique()


def wilson_ci(k, n, z=1.96):
    """95% Wilson score interval for a completion rate."""
    if n == 0:
        return (np.nan, np.nan)
    p = k / n
    denom = 1 + z**2 / n
    center = (p + z**2 / (2 * n)) / denom
    half = z * np.sqrt(p * (1 - p) / n + z**2 / (4 * n**2)) / denom
    return center - half, center + half


# ---------- 2. Task summary table ----------
rows = []
for tid, g in tasks.groupby("task_id"):
    k, n = g["success"].sum(), len(g)
    lo, hi = wilson_ci(k, n)
    ok = g[g["success"] == 1]
    rows.append({
        "task_id": tid,
        "task": TASKS.get(tid, tid),
        "n": n,
        "completion_rate": k / n,
        "ci_low": lo,
        "ci_high": hi,
        # task times are skewed, so report the median and the geometric mean
        "median_time_s": ok["time_s"].median(),
        "geo_mean_time_s": np.exp(np.log(ok["time_s"]).mean()) if len(ok) else np.nan,
        "mean_misclicks": g["misclicks"].mean(),
        "mean_seq": g["seq_ease_1to7"].mean(),
        "mean_confidence": g["confidence_1to5"].mean(),
    })
summary = pd.DataFrame(rows).sort_values("task_id")
summary.round(3).to_csv(OUT / "summary_by_task.csv", index=False)

# ---------- 3. SUS score (0-100) ----------
sus_items = survey[[f"sus_q{i}" for i in range(1, 11)]].to_numpy()
odd = sus_items[:, 0::2] - 1        # positive items: score - 1
even = 5 - sus_items[:, 1::2]       # negative items: 5 - score
survey["sus_score"] = (odd.sum(axis=1) + even.sum(axis=1)) * 2.5
survey = survey.merge(people[["pid", "fantasy_experience"]], on="pid", how="left")
survey[["pid", "fantasy_experience", "sus_score"]].to_csv(OUT / "sus_scores.csv", index=False)

# ---------- 4. Issues (coded from open-ended answers and screen recordings) ----------
issues = (tasks.dropna(subset=["issue_code"])
          .groupby(["issue_code", "task_id"])["pid"].nunique()
          .reset_index(name="participants")
          .sort_values("participants", ascending=False))
issues["share"] = issues["participants"] / N
issues.to_csv(OUT / "issue_frequency.csv", index=False)

# ---------- 5. Statistical tests ----------
lines = []
for tid, g in tasks.groupby("task_id"):
    table = pd.crosstab(g["fantasy_experience"], g["success"])
    if table.shape == (3, 2):
        chi2, p, dof, _ = stats.chi2_contingency(table)
        lines.append(f"{tid} completion by experience group: chi2({dof}) = {chi2:.2f}, p = {p:.4f}")
sus_groups = [survey.loc[survey["fantasy_experience"] == grp, "sus_score"] for grp in GROUPS]
h, p = stats.kruskal(*sus_groups)
lines.append(f"SUS by experience group (Kruskal-Wallis): H = {h:.2f}, p = {p:.4f}")
lines.append(f"SUS overall: mean = {survey['sus_score'].mean():.1f}, SD = {survey['sus_score'].std():.1f}")
(OUT / "stats_tests.txt").write_text("\n".join(lines))
print("\n".join(lines))

# ---------- 6. Graphs ----------
INK, INK2, GRID = "#1a1d27", "#5a6072", "#e3e5ec"
BLUE, ORANGE, GREEN = "#2a78d6", "#eb6834", "#1baf7a"
plt.rcParams.update({
    "font.size": 10.5, "axes.spines.top": False, "axes.spines.right": False,
    "axes.edgecolor": GRID, "xtick.color": INK2, "ytick.color": INK2,
    "savefig.dpi": 200, "savefig.bbox": "tight",
})
labels = [f"{r.task_id}  {r.task}" for r in summary.itertuples()]
y = np.arange(len(summary))[::-1]

# Figure 1: completion rate with 95% confidence intervals
fig, ax = plt.subplots(figsize=(8, 3.6))
rate = summary["completion_rate"] * 100
ax.barh(y, rate, color=BLUE, height=0.55)
ax.errorbar(rate, y, xerr=[rate - summary["ci_low"] * 100, summary["ci_high"] * 100 - rate],
            fmt="none", ecolor=INK, capsize=3, lw=1.2)
for yi, v in zip(y, rate):
    ax.text(v + 2, yi + 0.3, f"{v:.0f}%", fontsize=9, color=INK)
ax.set_yticks(y, labels)
ax.set_xlim(0, 105)
ax.set_xlabel("Completion rate (%) with 95% confidence interval")
ax.set_title(f"Task completion (n = {N})", loc="left", fontweight="bold")
ax.xaxis.grid(True, color=GRID)
ax.set_axisbelow(True)
fig.savefig(FIG / "fig1_completion.png")
plt.close(fig)

# Figure 2: time on task (successful attempts), box plot with points
fig, ax = plt.subplots(figsize=(8, 3.6))
order = list(summary["task_id"])
data = [tasks.loc[(tasks["task_id"] == t) & (tasks["success"] == 1), "time_s"] for t in order]
ax.boxplot(data[::-1], vert=False, widths=0.5, showfliers=False,
           medianprops={"color": INK, "lw": 2}, boxprops={"color": INK2}, whiskerprops={"color": INK2})
for i, d in enumerate(data[::-1], start=1):
    jitter = np.random.default_rng(1).uniform(-0.15, 0.15, len(d))
    ax.scatter(d, i + jitter, s=10, color=BLUE, alpha=0.5)
ax.set_yticks(range(1, len(order) + 1), labels[::-1])
ax.set_xlabel("Seconds to complete (successful attempts only)")

# Figure 3: ease (SEQ 1-7) and confidence (1-5) as two panels, since the scales differ
fig, axs = plt.subplots(1, 2, figsize=(8, 3.4), sharey=True)
for ax, col, top, title in [(axs[0], "mean_seq", 7, "Ease (SEQ, 1-7)"),
                            (axs[1], "mean_confidence", 5, "Confidence (1-5)")]:

R: data collection and cleaning r/01_collect_and_clean.R
# Sleeper New-User Usability Study - data collection and cleaning (R)
# Joshua Schulz | Independent portfolio project, not affiliated with Sleeper.
#
# The testing platform (or a Google Form) exports one row per participant.
# This script checks that export and turns it into the three clean files the
# analysis uses: participants.csv, task_results.csv, and survey.csv.
#
# Expected raw columns:
#   pid, age, fantasy_experience, device, used_sleeper_before,
#   T1_outcome, T1_time_s, T1_misclicks, T1_seq, T1_confidence, ... (same for T2-T5),
#   nav_ease, overall_confidence, sus_q1 ... sus_q10, confusing, liked, change

library(dplyr)
library(tidyr)
library(readr)

raw <- read_csv("data/raw_export.csv", show_col_types = FALSE)

# ---- 1. Screen out people who do not qualify ----
clean <- raw %>%
  filter(age >= 18, used_sleeper_before == "No") %>%
  distinct(pid, .keep_all = TRUE)

cat("Kept", nrow(clean), "of", nrow(raw), "participants after screening\n")

# ---- 2. Participants file ----
participants <- clean %>%
  select(pid, age, fantasy_experience, device, used_sleeper_before)
write_csv(participants, "data/participants.csv")

# ---- 3. Task results: wide to long (one row per participant per task) ----
task_results <- clean %>%
  select(pid, matches("^T[1-5]_")) %>%
  pivot_longer(
    cols = -pid,
    names_to = c("task_id", ".value"),
    names_pattern = "^(T[1-5])_(.*)$"
  ) %>%
  rename(seq_ease_1to7 = seq, confidence_1to5 = confidence) %>%
  mutate(
    outcome = tolower(outcome),
    # anything over the 180 second cap counts as a failure
    outcome = if_else(time_s > 180, "fail", outcome),
    issue_code = NA_character_   # filled in later while coding recordings
  )

# ---- 1. Task summary with 95% Wilson confidence intervals ----
wilson <- function(k, n, z = 1.96) {
  p <- k / n
  center <- (p + z^2 / (2 * n)) / (1 + z^2 / n)
  half <- z * sqrt(p * (1 - p) / n + z^2 / (4 * n^2)) / (1 + z^2 / n)
  c(center - half, center + half)
}

summary_by_task <- tasks %>%
  group_by(task_id, task_label) %>%
  summarise(
    n = n(),
    completed = sum(success),
    completion_rate = mean(success),
    ci_low = wilson(completed, n)[1],
    ci_high = wilson(completed, n)[2],
    median_time_s = median(time_s[success == 1]),
    geo_mean_time_s = exp(mean(log(time_s[success == 1]))),
    mean_misclicks = mean(misclicks),
    mean_seq = mean(seq_ease_1to7),
    mean_confidence = mean(confidence_1to5),
    .groups = "drop"
  )
write_csv(summary_by_task, "output/summary_by_task_R.csv")
